# Decision: planning skills switch from Markdown to planf3 HTML + manual image generation

**Context**: FABLE-HARNESS's two planning skills (`plan-deep`, `plan`) originally shipped a **Markdown** output surface, with a deliberate note that planf3's HTML-first, image-generating design was "cosmetic overhead this harness explicitly skips" (prior `plan-deep/SKILL.md:25`; rationale at `plan.md:273`). During last session's goal-verification research it surfaced that disler's **planf3** ("Plans For Fable 5") — the very skill ours is named after and modeled on — is genuinely **HTML-first with per-section image generation**, not Markdown. The user asked to reverse the simplification and adopt planf3's real design, with a hard emphasis on **manual image-generation prompts for when API credits are low**.

**Decision**: Both planning skills now emit a single self-contained **HTML** plan (embedded CSS design system, planf3 section structure, inline `[]`/`[wip]`/`[x]`/`[f]` status chips, append-only `<details class="meta">` metadata + Amendments, conditional Questionables) built from shared templates in `.claude/skills/lib/` (`plan-template.html` full for `plan-deep`; `plan-template-lite.html` for `plan`). Each plan carries `<figure>` **image slots** (`<!-- {{...IMAGE: <basename> | <subject>}} -->`) plus a graceful "image pending" placeholder, so a plan is fully usable with zero images. Image generation is **manual-only for now**: a local, no-network, no-MCP CLI (`plan-images.ps1` primary + `.sh` mirror) `extract`s a copy-paste prompt sheet (subject + universal 1536×1024 style spec + target path) and later `apply`s — swapping each slot whose PNG exists for an `<img>` (idempotent). No image API is called by the harness.

**Alternatives considered**: (a) keep Markdown — rejected, diverges from planf3 and from the user's explicit request; (b) HTML with an auto-API image generator (OpenAI `gpt-image-2`, as planf3 ships) wired on by default — rejected for now because the user prioritized the low-credit/manual path and an always-on external API dependency is heavier than needed; (c) HTML with a manual-first pipeline (prompt sheet + swap-in), auto-API deferred as a future third subcommand — **chosen**.

**Chosen**: (c). It matches planf3's real design and the user's stated need exactly, keeps the low-credit path first-class, and — critically — introduces **zero network/MCP dependency** into the harness's own operation (CONSTITUTION.md **N8**: the image pipeline is a local CLI only). The implementation was orchestrated through **Hydra** as an external construction crew (garland creative squad authored the CSS design system + image-prompt conventions via its non-MCP `claude-skill` path), while **FABLE-HARNESS itself stays completely independent** — no Hydra/MCP/pp artifact was landed in the repo, and the finished harness runs identically whether or not Hydra exists on the machine.

**Consequence**: Added `.claude/skills/lib/{plan-template.html, plan-template-lite.html, plan-images.ps1, plan-images.sh, README.md}`. Rewrote `plan-deep/SKILL.md` and `plan/SKILL.md` to HTML output (each with an explicit N9 Preserved-Invariants-vs-Changed-Behaviors block); `plan-deep` retains its sole `model: fable` + `disable-model-invocation: true` gate (N2) and Step-0 approval-token flow unchanged. Narrowed `designer.md`'s "no image-generation tool" assertion so it stays true (designer still renders no product-UI pixels; the plan-diagram pipeline is a separate planning-only tool). Appended an amendment to `plan.md` reversing the prior call. Recorded preserved invariants in `memory/invariants.md`. Output convention: `.fable/<run_id>/artifacts/<slug>.html` inside a run, else top-level `specs/<slug>.html`, sibling `<slug>/` PNG folder either way. Cites **N2** (no second Fable surface), **N8** (local-CLI-only, no MCP/network), **N9** (revision discipline).

**Owner**: harness maintainer. **Review date**: revisit when wiring the deferred auto-generation subcommand (`plan-images … generate`), or if a Claude-native image tool becomes available (which could replace the manual/external step without any template change).
