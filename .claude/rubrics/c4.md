# Rubric: C4 system-context / architecture stability

Applies to: architecture artifacts from `architect.md` (§4.6).

## Checks

1. At minimum a System Context diagram (Mermaid) exists showing the system's boundary and its external actors/systems.
2. Every major internal boundary (container-level decomposition) is named with an explicit reason for the boundary (not decomposition for its own sake).
3. Every ADR has all six required fields: Context, Decision, Alternatives Considered, Consequences, Owner, Review Date (per taxonomy_blueprint.md §8.3 / §14).
4. No architectural decision silently reverses a prior ADR without an explicit supersession note.
5. Reliability/scalability assumptions are stated explicitly, not left implicit.

## Verdict mapping

- `pass`: all 5 checks satisfied.
- `pass-with-notes`: checks 1-3 satisfied, 4 or 5 has minor gaps.
- `reject`: missing System Context diagram, or an ADR missing a required field, or a silent supersession.
