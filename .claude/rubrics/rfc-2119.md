# Rubric: RFC-2119 normative language stability

Applies to: PRDs, feature specs, acceptance criteria, ADRs (§4.3, §4.6 artifacts).

## Checks

1. Every normative requirement uses exactly one of MUST / MUST NOT / SHOULD / SHOULD NOT / MAY (RFC 2119 keywords), not ambiguous language like "should probably" or "needs to".
2. Every MUST/MUST NOT statement is independently testable — a reviewer could write a pass/fail test from the sentence alone.
3. No requirement silently contradicts an entry in `memory/invariants.md` (cross-check; if it does, the artifact must state this as a Changed Behavior per CONSTITUTION N9, not silently override it).
4. Edge cases and failure behavior are stated explicitly, not left implicit ("happy path only" specs fail this rubric).
5. Acceptance criteria examples are concrete (real values/inputs), not placeholder ("e.g. some value").

## Verdict mapping

- `pass`: all 5 checks satisfied.
- `pass-with-notes`: checks 1-3 satisfied, 4 or 5 has minor gaps noted explicitly.
- `reject`: any of checks 1-3 fails, or the artifact silently contradicts a preserved invariant.
