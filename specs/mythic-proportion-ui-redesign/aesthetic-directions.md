# mythic-proportion — Aesthetic Direction Exploration

**Design dials**: no `.fable/<run_id>/profile.json` was resolvable for this exploration task (it is standalone, not dispatched inside an active run). Per the designer contract, all three dials default to the middle value and that default is stated explicitly here, not silently overridden by personal taste:
- DESIGN_VARIANCE = 5 (defaulted)
- MOTION_INTENSITY = 5 (defaulted)
- VISUAL_DENSITY = 5 (defaulted)

Each direction below adjusts *how* it expresses these mid-point dials (a solo power-user tool can still lean distinctive without claiming a high-variance dial override); if the user picks a direction and later supplies real dial values via a run profile, `design-system-curator` should re-derive component-library specifics from those values, not from this document's illustrative framing.

These are three candidate directions for the whole app (component tokens, type, motion, density), illustrated concretely through the ingest page — currently a plain drop-zone in `IngestView.tsx`. No winner is chosen here; present as options.

---

## Direction A — "Excavation" (mineral, instrument-panel)

A dig-site instrument panel: the knowledge base is treated as strata being excavated and cataloged, not a friendly consumer product. Palette stays on the existing dark neutral-260° OKLCH ramp but narrows the accent to a single desaturated ochre/rust (hue ~55-70, chroma 0.08-0.12) against near-black neutrals — no blue-violet "tech" accent, no gradients. Status colors (danger/success/warning) are kept but muted to match the mineral family rather than saturated stoplight colors. Type: a monospace-forward pairing — `ui-monospace`/`SFMono-Regular`/`Consolas` for all data/status/labels (job IDs, counts, file names), `system-ui` only for prose/paragraph copy — ratio 1.25, reinforcing "instrument readout" over "app chrome." Spacing is compact-to-medium (base 4px grid, dial=5): panels sit close together like a control console, not airy. Motion is deliberately restrained — no bounce/spring easing; progress fills move linearly, panel entry is a 120ms opacity+2px translate, nothing "delightful," because the whole point is that this reads as instrumentation, not marketing.

**Ingest page, in Excavation**: the dropzone is a flat-bordered rectangle (1px solid neutral-300, no rounded corners beyond `radius-sm`) labeled in mono uppercase tracking, "DROP FILES / SELECT FILES" — deliberately terse, no exclamation, no icon illustration. *Default*: flat border, low-chroma ochre corner ticks (like a scan-target reticle) at the four corners instead of a full colored border. *Hover*: border brightens to full ochre-500, corner ticks extend slightly (transform only, no shadow bloom). *Focus*: a 2px ochre focus ring offset 2px, visible via `:focus-visible`, meets 3:1 non-text contrast against the dark background. *Active* (mid-drag-over): background shifts to neutral-100, ticks pulse once (one keyframe, not looping — avoids motion-sickness from a looping pulse during a drag the user is actively controlling). *Loading*: the file list becomes a table-like mono readout, each row an entity line (`filename … STATUS`), with a single hairline progress bar (no rounded pill) tracking `settledCount/files.length` — width transitions are linear-eased, updating on each poll tick, not artificially smoothed. *Empty*: before any job exists, the dropzone is the sole element — no illustration, a one-line mono caption ("no active ingest job") sits below it in neutral-400. *Error*: error panel gets a 2px left rule in danger-400 (not a full red fill — reserves saturated red for genuine failure emphasis) with the raw error string in mono, matching "instrument fault log" framing; retry action is a text-style button, not a modal. *Disabled*: "Build Knowledge Graph" while `graphBuilding` is true shows reduced-opacity (via semantic `--opacity-disabled` token, not just a lighter color, to stay contrast-safe) label text changes to "BUILDING…" in mono, cursor `not-allowed`.

## Direction B — "Mycelial" (organic network, calm)

Leans into the "living knowledge graph" concept directly: the product *is* a network of interconnected notes, so the whole UI's visual language borrows from organic branching/root systems rather than dashboard chrome. Palette: dark-emphasis but with a wider hue spread than Excavation — a muted teal-green primary (hue ~160-170, chroma 0.10-0.14, "moss/lichen" rather than "mint") plus the existing categorical community ramp used sparingly as accent dots, never as large fills. No gradients, but subtle 1-2% luminance steps between adjacent surface layers (still flat colors, just closely-spaced ramps) to suggest depth without literal blur/glow. Type: humanist system-ui pairing — `system-ui`/`Segoe UI`/`San Francisco` for everything, no monospace except literal file paths/IDs — ratio 1.333 (slightly more expressive scale than Excavation) because this direction wants prose (notes, entity descriptions) to breathe. Spacing: generous (dial pushed toward 3-4 in feel even though baseline is 5) — more line-height, more panel padding — because this is a *reading and thinking* tool, and cramped ingest-status readouts would fight the "calm second brain" premise. Motion: organic easing (custom cubic-bezier resembling a settling/branching motion, ~200-280ms) — things "grow into place" rather than snap; a subtle looping "breathing" affordance only on genuinely long-running states (the graph-build spinner), never on static UI.

**Ingest page, in Mycelial**: the dropzone is borderless-until-interaction — a soft-cornered (`radius-lg`) region with no visible edge in its default state, just a centered line-icon-free instruction in prose type: "Drop files, or click to browse." *Default*: no border, background one step lighter than the page. *Hover*: a hairline moss-teal border fades in (150ms), plus a very slight (1-2px) upward translate — restrained, not springy. *Focus*: a 2px teal focus ring, `:focus-visible` only, same WCAG non-text contrast floor as Direction A. *Active*/drag-over: border solidifies to full teal-500 and background shifts one step lighter; a single soft "root tendrils" line-drawing animation (SVG stroke-dashoffset, one-shot, ~300ms, respects `prefers-reduced-motion`) traces from the drop point — this is the one place this direction spends its "living graph" motion budget deliberately, not everywhere. *Loading*: file rows appear as a vertically-growing list, each new row using the branch-easing entry; the progress bar is a continuous teal fill with rounded ends (matches `radius-full` token) since this direction *does* use soft edges intentionally, unlike Excavation. *Empty*: pre-job state shows the same calm instruction text plus a one-line reassurance ("Files stay on this machine"), reinforcing local-first trust rather than an empty illustration. *Error*: error panel background tints warmly (danger-400 at low alpha as a wash, not a hard rule), text stays high-contrast; a retry affordance sits inline. *Disabled*: "Build Knowledge Graph" during build shows a slow single-loop breathing opacity (respecting reduced-motion by falling back to static reduced-opacity), label "Growing the graph…".

## Direction C — "Ledger" (dense, archival, no-nonsense)

The most information-dense and least illustrative of the three: treats mythic-proportion as a serious archival/reference tool (library card catalog, not a lab instrument or a garden) for a power user who wants maximum information per screen and minimal chrome. Palette: near-monochrome — neutrals only, plus a single restrained blue-gray accent (hue ~230-240, chroma 0.06-0.09, distinctly less saturated than the current `--accent-500`) used only for interactive/actionable elements; status colors are the only saturated hues on screen, and only ever appear as small badges/text, never backgrounds. Type: a classic two-family pairing — `system-ui` for UI chrome at a *smaller* base size than the current 1rem default (dial pushed toward 7-8 density: 0.875rem base), `ui-monospace` for all tabular/status data — ratio kept tight at 1.2 (less dramatic size jumps, more size *steps*, because density wants more distinct legible tiers, not bigger headlines). Spacing: compact, dense grid — 4px base with most component padding at `space-2`/`space-3` rather than `space-4`/`space-5`; this direction explicitly maximizes rows-of-information-per-viewport (many files visible in the ingest list without scrolling). Motion: near-static, functional-only — state changes are near-instant (80-120ms opacity/color transitions), no translate/scale flourishes anywhere; this direction treats motion as a courtesy for "did my click register," never as brand expression.

**Ingest page, in Ledger**: the dropzone is a thin dashed-border rectangle (a genuinely different visual, not just color) with left-aligned instructional text — reads like a form field, not a hero element. *Default*: 1px dashed neutral-300 border, compact height. *Hover*: dash becomes solid, accent-colored, no movement. *Focus*: 2px solid accent focus ring, `:focus-visible`. *Active*/drag: background tint one step, border stays solid — no ticks, no tendrils, deliberately quiet. *Loading*: file list renders as an actual dense table (filename column, status column, message column) with a slim linear progress bar above it — every row is single-line-height, so 30+ files are visible without scrolling on a normal viewport; polling updates re-render only the changed cell's text color, not the row layout. *Empty*: an explicit "0 files queued" line in the same table-header style used when populated, so the empty state visually previews the populated state's structure (teaches the UI by showing its own skeleton). *Error*: error text appears inline in the affected row's message column in danger-400 text (not a separate panel) — errors are ledger entries, not interruptions; a page-level error (e.g., upload endpoint failure) still gets a compact top-of-list banner with a text retry link. *Disabled*: "Build Knowledge Graph" shows reduced-opacity plus a small inline mono status suffix ("(running)") rather than changing the button's label text, keeping the label itself stable for scannability.
